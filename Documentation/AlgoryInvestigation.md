# Algory engine investigation (initial findings)

## Finding

The strongest candidate for the strategy-generation process is the installed `Engine.exe` at `C:\Users\Jacob\AppData\Local\Algory\Engine.exe`. It is a 144.6 MB x64 PE containing a PyInstaller archive with CPython 3.13. The archive includes a 2.69 MB entry named `Algory_Engine_v129`; this is distinct from the dashboard and HUD executables.

This identifies the campaign engine process and runtime, but not the implementation of its calculations. The entry is a PyArmor loader. Its top-level code imports `pyarmor_runtime_011532`, calls `__pyarmor__`, and passes a 2,689,144-byte opaque payload. REA found one top-level code object and no nested Python functions to inspect. `Algory_Genes_v16` has the same loader shape with a 710,801-byte payload. I did not try to bypass the protection.

A controlled runtime profile now confirms the campaign path: the local HUD server launched `Engine.exe`, which in turn launched additional `Engine.exe` worker processes. The engine verified a Free license, tried MT5 three times, fell back to built-in history, and began processing XAUUSD H2. It fetched 2,205,629 one-minute bars (the log reported 46 MB) before the campaign was stopped at 0% in Proving Grounds. The protected strategy-generation stage was not reached, so this run identifies the executable and its orchestration/data path, not the actual breeding algorithm.

## Language, local/cloud, and paid features

The packaging and engine-entry evidence point to Python 3.13 under PyInstaller, with PyArmor protecting the main Python payload. The bundled MetaTrader 5 Python package and MQL5 chart manager support an MT5 integration path. The app also packages scientific/backtesting libraries, but static inclusion is not proof of use.

The current public [product page](https://algory.app/) and [how-to guide](https://algory.app/g/algory-how-to-use.html), reviewed 2026-10-28, document the following vendor claims. They describe intended product behavior; they do not prove that each path executed in the installed build.

- **Search:** two populations named Consistency and Growth run for 20 generations each, followed by a Final War. The page says only genes that passed MT5 parity may continue breeding. Pro Smart mode seeds half of each starting population from prior winners for the same market and leaves half random. Campaign history can be Focused (about three years) or Deep (about six years); campaigns can be scheduled.
- **Validation and scoring:** the first 70% of history is used for training and the last 30% is held out. The public page says finalists must beat most of 100 random strategies, pass 1,000 shuffled-trade drawdown simulations (rejecting adverse outcomes above 40% drawdown), and retain profitability in at least half of parameter nudges; fewer than 15 held-out trades is rejected. It lists an eight-part score: Persistence 20, Recovery 15, Sharpe 15, Trades 15, held-out linearity 12, max drawdown 10, profit factor 10, and in-sample linearity 3. The precise calculations and the displayed thresholds are vendor descriptions, not reproduced source.
- **Vault and portfolios:** each strategy passport is said to expose its genes, train/held-out curve, statistics, score, and grade. Portfolio health uses correlation, exposure, health, concentration, and size; any pairwise return correlation at or above 0.9 caps the displayed grade at D. Portfolio creation, weights, and score internals have not been observed in the binary.
- **MT5 deployment and parity:** the guide describes compiling portfolio members to standard MT5 Expert Advisors, copying them into MT5, and running a broker-data parity comparison. The product page describes trade-by-trade matching for entry, exit, and size, with A/B/C/D/F score bands. The local MQL5 `Chart_Manager.mq5` is a separate chart and account-management helper; its source explicitly says it never opens a trade. This does not establish that the protected engine's EA-generation code is present in the free installation.
- **Costs, decay, and account rules:** public claims include commission, broker-tick-derived hourly spread, swaps, slippage, M1 sub-bar checks, and daylight-saving handling; reassessment after 15 new trades; decay alerts on a five-point score drop or negative expectancy; and a 25/50/100% risk-incubation ladder. The described account rules include daily drawdown, aggregate risk, symbol lock, optional profit target and margin ceiling, news filter, and Friday close. These behaviors remain unverified in the installed app except where independently noted in this report.
- **Entitlements:** the product page says Free has the full breeding engine, Gold/USDJPY/USDCAD on H1 or H2, Eco/Medium power, and a scored vault. Its paid plans advertise all markets/timeframes, High/Extreme power, Smart mode, multi-timeframe context, deploy/parity/refresh/reassess, portfolio diversity grading, automation/incubation, and live bot monitoring. This is a public plan matrix, not a subscription-system audit. The observed installation verified a Free license only; paid behavior and whether it uses the same local modules or remote services remain unknown.

The local install has one `Engine.exe`; that alone does not prove whether paid features share the same code, are gated locally, or depend on a service. The public pages say campaigns use the user's CPU and built-in history can be used without MT5. In the observed Free campaign, the local engine process tree fetched built-in history from remote HTTPS endpoints; the location of strategy evaluation was not proven.

REA reopened `C:\Users\Jacob\AppData\Local\Algory\Engine.exe` and matched SHA-256 `bf2c2787254f9bb27827b59eca7c151dfba2e71ec19d66f9cfd2183c975cde2b` (x86-64 PE). The retained `inspect_artifact` summary is Evidence `ev_7aeb620134b4e9c41afdb81e3e150c8d0e7bc0ba7b82d24375b36a18abcac4a7`; it confirms a complete PyInstaller container inventory with 3,356 archive entries, 7,616 file occurrences hash-verified, zero mismatches, and CPython 3.13 metadata. The focused inventory view is Evidence `ev_e40aca935742bffc131e30b8afc276b1cf55d71e7ce9ea45d72c99d578a67cc0`: it records `Algory_Engine_v129` as a verified 2,689,375-byte archive entry and `PYZ.pyz/Algory_Genes_v16.pyc` as a verified compressed entry of 711,256 bytes. The `Genes` uncompressed size is not declared in the PYZ table. These are shipped-artifact observations; they do not expose the protected calculation payload or establish runtime function calls.

The evidence separates the runtime into three observable parts: the browser UI talks to the HUD over loopback; the HUD starts local engine processes; and an engine worker contacts remote HTTPS endpoints while acquiring built-in market history. This confirms that the campaign depends on a network service for a missing local history cache. It does not show that the strategy search or backtests run remotely. The engine process and its local workers load the campaign, consume local memory/CPU, and report campaign status, but this short run stopped before a generation result. Thus the evidence supports a local calculation runtime with remote data/service calls, while the location of the actual candidate evaluation remains unproven by this run.

## Confirmed versus unresolved

**Confirmed by shipped files and static inspection:** the candidate engine location, CPython/PyInstaller packaging, PyArmor-protected engine and Genes payloads, bundled MT5/backtesting-related packages, separate dashboard/HUD apps, local HUD listener, UI endpoint strings, and the MT5 helper's chart/order-management responsibilities.

**Still unresolved:** the exact genetic representation, mutation/selection/fitness/backtest algorithms; whether the optimizer uses CPU threads or native extensions; whether paid features are in this binary and how they are gated; what the second remote HTTPS endpoint serves; whether EA generation is local; and the exact generated EA structure. The run did not get far enough to produce a strategy or observe candidate evaluation.

The controlled run is complete and was stopped from the UI at 0% before strategy results were produced. The temporary profiling settings (Eco power, 10 candidates, one generation per phase) were restored to the previous Medium / 3,000 / 20, 20, 10, 20 campaign configuration. No licensing controls were bypassed. To inspect candidate generation itself, a separate controlled run would need an authorized campaign environment with the required history available; the present evidence is enough to identify the engine executable and the local/cloud boundaries around startup and data acquisition.
