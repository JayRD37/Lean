# Genetic strategy discovery for LEAN

This branch adds an independent, deterministic genetic search module and connects it to LEAN's existing optimizer and backtest runner. The Algory investigation remains behavioral research only; no Algory executable, service, protected code, or license mechanism is used here.

The repository baseline is upstream LEAN commit `22404ea28b8d3f3c9eb74d6ed9f0444426f8e417`, verified as upstream `master` on 2026-10-28. GitHub's latest non-prerelease tag is `v2.4.0.1` from 2017, so the fork uses the current upstream source head instead of that old release tag. The full source SHA plus the SDK pin makes the build baseline reproducible.

## Architecture

- `StrategyDiscovery/QuantConnect.Genetic.csproj` is the standalone engine. A genome selects long-only trend-following, mean-reversion, or breakout logic, a primary minute/hour/daily resolution with an optional slower timeframe confirmation, moving-average and volatility periods, entry/exit thresholds, position count, and gross exposure. The breakout family enters above a shorter high channel and exits below a longer low channel, both computed from completed prior bars. Higher-timeframe filters are built from LEAN consolidators over the primary subscription, and an active filter must be ready and directionally agree before the primary signal can create a portfolio target.
- `Optimizer/Strategies/GeneticSearchOptimizationStrategy.cs` implements LEAN's `IOptimizationStrategy`. It submits candidate parameter sets to LEAN; `ConsoleLeanOptimizer` starts independent LEAN processes and bounds concurrency. Growth and Consistency populations evolve separately. Random candidates provide a baseline.
- Universe selection defaults to the fixed `discovery.symbols` list. Optional `discovery.universe-mode=TopDollarVolume` selects up to `discovery.universe-size` US equity securities daily from LEAN point-in-time coarse data, using a $5 minimum price and $25 million minimum dollar volume. Configured symbols remain as anchors and may include ETFs. Newly added securities receive indicator and return-history warmup; removed securities are liquidated before active strategy state is dropped. Optimizer and paper universe modes and sizes must match, and the supervisor checks this before starting.
- `Algorithm.CSharp/GeneticDiscoveryAlgorithm.cs` evaluates one genome using LEAN securities, indicators, portfolio targets, brokerage fees, and slippage. U.S. equity orders use `AlpacaEquityRegulatoryFeeModel` for estimated CAT fees on buys and sells plus SEC and FINRA TAF fees on sells. Its live-mode guard requires explicit strategy opt-in, `alpaca-paper-trading=true`, and the `AlpacaBrokerage` adapter; other live brokerage adapters are rejected. It budgets remaining position slots and gross exposure after existing holdings outside the managed symbol set, and emits zero targets only for its managed symbols when signals disappear or shutdown is requested. Portfolio correlation uses exact shared return intervals; a candidate is excluded while a pair has fewer than 20 aligned samples. Intraday equity target changes are deferred until a regular-session bar so LEAN does not turn an after-hours market order into a brokerage-invalid market-on-open order. `StrategyDiscovery/PortfolioDrawdownGuard.cs` persists the account high watermark and a latched drawdown trip across LEAN process restarts; the paper supervisor stops optimization/restarts after a trip. A file-based emergency stop is checked on data events. Brokerage disconnects pause new target submissions and liquidation orders until reconnection; an invalid order latches the execution safety gate, with liquidation deferred to the next data event to avoid reentrant order submission, and stops the algorithm when flat. Simulated market orders add a configurable half-spread floor (default 5 basis points full spread) plus LEAN's volume-share impact model; the spread floor is an assumption, not quote-derived execution data. The equity regulatory fee estimate uses Alpaca's fee schedule revised 2026-09-17.
- Training generations are scored on the configured training dates. Finalists from both evolved populations and random candidates are rerun across contiguous chronological windows in the disjoint validation date interval. Evolved finalists also get deterministic one-axis parameter probes around their fast/slow periods, entry/exit thresholds, and available slower confirmation timeframes. A finalist must finish every central window, satisfy constraints in every central window, and have valid results for every requested probe. Its score is the lower of central lower-median fitness and neighbor lower-median fitness. After all validation candidates have been compared, exactly one highest-scoring eligible evolved candidate is run once on the later, disjoint confirmation interval. This final period is not used to choose among candidates; it is the sole basis for optimizer `Solution` and a required gate for paper eligibility. JSONL evaluation history and ranked training/validation/confirmation records are written under LEAN's results folder. The ranking file compares evolved finalists with the median held-out random baseline and records probe count, valid probe count, weakest neighbor fitness, and fitness delta. When LEAN provides closed trades, history includes both a seeded IID bootstrap and seeded without-replacement trade-order permutations, with 1,000 permutations by default, recording 95th-percentile and worst drawdown plus the fraction above the 40% diagnostic threshold.
- The example algorithm runs scheduled health reviews every configured number of calendar days, emits a reoptimization request in its log, and retires after repeated negative review periods or a configured drawdown. The paper supervisor consumes reoptimization requests, validates a newly selected genome against the configured promotion thresholds, and restarts only an approved paper session.
- Alpaca is a separate official LEAN brokerage plugin. Run `pwsh ./scripts/setup-alpaca-plugin.ps1` before enabling paper deployment. The installer checks out plugin commit `b92d6ecd391d5a79e91b060668d1ea4fafec9b89`, pins its LEAN package references to `2.5.18208`, and builds the adapter into `plugins/alpaca`. Configure `alpaca-plugin-directory` in `examples/genetic-discovery/supervisor.json` to that directory. The supervisor refuses to start without the adapter and `Alpaca.Markets.dll`, and passes the validated folder to LEAN's `plugin-directory` loader. The staged directory preserves the upstream plugin README and includes Apache-2.0 license notices for both the QuantConnect plugin and its Alpaca SDK dependency. Focused CI builds the plugin and runs its offline factory/composition test; broker connection and account tests require Alpaca credentials and are not run here. No broker session is claimed without Alpaca paper credentials.
- CI NuGet audit reports advisories in inherited LEAN/plugin dependencies, including `System.Drawing.Common` 4.7.0 (NU1904), `DotNetZip` 1.16.0 (NU1903), and `MessagePack` 3.1.7 (NU1902). These advisories have not been triaged or upgraded in this branch; review the dependency tree before any production deployment.

The engine's seeded generator makes candidate creation and evolution reproducible. Evaluation order does not affect the next generation because breeding begins only after every candidate in that generation has completed. LEAN's optimizer controls process concurrency. Randomized-baseline comparisons report the empirical tail probability and its Bonferroni adjustment across evolved validation finalists. This controls finalist comparison multiplicity only; it does not correct the training-stage search or the fact that randomized baselines are selected by training fitness. Treat the values as diagnostics, not confirmatory evidence. The default example validates two random baselines, too few to resolve a 5% tail threshold; increase `validation-baseline-count` and `random-baseline-size` for finer resolution. Paper promotion requires an evolved candidate to beat the validation baseline median, pass walk-forward and parameter robustness gates, and have a passing result in the untouched confirmation interval. The single confirmation result is not a statistical comparison against the randomized baseline.

## Build and run a local discovery search

The SDK is pinned in `global.json` to .NET SDK 10.0.403. Build from the repository root, then launch the optimizer with the checked-in config:

```powershell
dotnet build QuantConnect.Lean.sln
Push-Location Optimizer.Launcher/bin/Debug
dotnet QuantConnect.Optimizer.Launcher.dll --config ../../../examples/genetic-discovery/optimizer.json
Pop-Location
```

`optimizer.json` is a modest search example with three chronological validation windows and four parameter probes per evolved finalist. After walk-forward selection, the optimizer runs exactly one final confirmation backtest on the selected evolved genome; only that result can become `Solution` or qualify for paper promotion. The confirmation range must be later than and disjoint from both training and validation. `optimizer-smoke.json` runs eleven LEAN backtests against the March 2021 SPY data archive, with one validation window, one probe per evolved finalist, and a final untouched March 15–31 confirmation window. Ensure LEAN's matching US equity data is installed before running. Result and LEAN launcher paths are relative to `Optimizer.Launcher/bin/Debug`.

The genetic optimizer is self-starting: it generates its own genome parameter sets and does not require an input `parameters` range. LEAN's other optimization strategies retain the existing non-empty parameter requirement.

To use point-in-time coarse-universe selection, set `universe-mode` to `TopDollarVolume` and `universe-size` to the same value in optimizer settings and paper overlay parameters (`discovery.universe-mode` and `discovery.universe-size`). The checked-in examples default to `Configured`. The local integration fixture uses the 2014 coarse archive; local coarse coverage is sparse, and availability of coarse selection in an Alpaca live-data session has not been verified.
